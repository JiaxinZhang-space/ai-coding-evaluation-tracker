# Course submission checklist

## Before implementation

- [ ] Confirm enrolled cohort, Project 2/attempt meaning, deadlines and certificate conditions on the course platform.
- [ ] Recheck official rubric for changes before final submission.
- [ ] Keep the first specification commit before application code.

The provided official page describes a final project with two attempts; it does not separately define a different Project 2 rubric. This repository follows the supplied page. Personal deadline and eligibility details remain UNVERIFIED.

## Before submission

- [ ] Clean clone and run using the single documented startup command.
- [ ] Run all tests with the single documented verify command.
- [ ] Verify persistence across container recreation.
- [ ] Inspect deployment/demo and rollback evidence.
- [ ] Link actual PR CI runs and feature evidence.
- [ ] Score each rubric item using evidence at the submission SHA.
- [ ] Ensure public tracker, repository and evidence are readable without account access.
- [ ] Check all sample data is synthetic and no private information is published.
- [ ] Tag the tested release and record the exact commit.
- [ ] Human owner submits through the course platform.

## After submission

- [ ] Complete three assigned peer reviews by the platform deadline.
- [ ] Record platform confirmation of review completion locally.
- [ ] Verify course completion/certificate eligibility and issuance on the platform.

Repository quality cannot substitute for the three peer reviews or platform eligibility requirements.
